Every event `createSandboxChatProducer` yields now leaves through one person-facing filter, so no failure reason or tool list reaches a client by any path. A raw harness error, a failed `status` or `done`, a `session.run.failed` and a `session.error` read the failed-turn sentence like the terminal error, with the reason logged once at warn and kept for the route's hooks. A harness warning whose reason is withheld is logged once and dropped: no notice, nothing on the wire. A raw harness tool event, a recovered assistant row and a live tool part never carry the list of every tool, while a completed tool's output (a document it read) and every tool input stay whole. A funding, billing, admission or policy refusal keeps its own words without the harness wrapper (its `execution failed:` prefix, a tool list and an exit status), and a plainly worded failure no longer puts its raw text in `details.raw`. With `redactValues`, the route's failure hooks still receive the real reason, redacted. A protected turn whose settlement check fails after its full answer still ends failed, as before, but the person reads "The answer above is complete." instead of being asked to send again. A closed-set `reason` code on a failure event stays as it is.
