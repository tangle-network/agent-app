Every event `createSandboxChatProducer` yields now leaves through one person-facing filter, and a person reads only sentences agent-app wrote. Harness, provider and Router text is read only to classify a failure, by its code, HTTP status or a recognized phrase; the person reads that class's fixed sentence, and no part of the reason is shown. The only values in a sentence are times parsed and formatted here.

The classes: a runtime failure reads the failed-turn sentence; a refused model key, a provider wait (with its reset time), an exhausted key budget, a low balance, a funding refusal (402, `PAYMENT_REQUIRED` or a reason the recovery UI knows, in the recovery UI's own title and message), a model policy refusal, an unsupported grant model, a missing grant activation and an unsupported profile each read one fixed sentence, with their code kept. A model failover trail (`All N model(s) failed. …`) is classified by its last attempt only. A settlement failure after answer text reads "The answer above is complete." and the turn still ends failed.

Every failure carrier (an `error`, a failed `done` or `status`, a `session.run.failed`, a `session.error`, a raw harness error, retry, `turn.failed` or error item, and the detached result) has each text field replaced by the class sentence, and its `details` keeps only `code`, `statusCode`, `retryable`, `retryAt` and `class`. The reason is logged once at warn with its class, and the route's failure hooks still receive it (redacted with `redactValues`). Only allowlisted warning codes reach the person, as a notice sentence written for each code; any other warning is dropped and logged once as a `harness_warning`. A provider retry notice reads "The model provider is busy; retrying at HH:MM:SS UTC." A raw harness tool event, a recovered assistant row and a live tool part never carry the list of every tool, while a completed tool's output and every tool input stay whole.
