A failed sandbox turn no longer shows the person the harness's own failure text (its error, the refused tool, the list of every tool, a repeated-call report or a stack). `createSandboxChatProducer` puts one plain sentence in the streamed text, the stored assistant row, the error notice and the error event's `message`: "That answer stopped before it finished. Please send your question again.", or the product's `failedTurnText`. A partial answer already streamed is kept, with only the sentence after it. The raw reason goes to the producer's `log` (`console.warn` when unset) as `failureClass: 'runtime_failure'` with the event's code; the error event drops `details.failureNote`, and `onTurnComplete`'s `failureReason`, the detached result's `error` and turn-timing failure text read the sentence. Every failure code is unchanged. These keep their words: a provider reset and a refused model key, which the producer already words plainly, and a funding, billing or admission refusal, which is a failure with HTTP status 402 or one the client's recovery UI reads (`getChatFundingRecovery`: `insufficient_credits`, `paid_access_required`, `funding_required`, or the words "insufficient credits" or "inference requires verified paid access"). Turn-health and journey scoring recognise the new sentence as a failure. `getChatFundingRecovery` moves to the browser-safe `web` module and is still exported from `web-react`.
