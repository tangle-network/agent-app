Record the harness's own token cost beside the ledger charge. Sandbox 1.0.264 made `PromptResult.costUsd` the Platform ledger charge only, so a failed native turn recorded `cost_usd = null` and its model spend disappeared. `ChatTurnUsage.harnessCostUsd` and `OperatorTurn.harnessCostUsd` carry the harness-reported cost; `costUsd` holds only the ledger charge. The chat-store `harness_cost_usd` column is opt-in: a table that declares `harnessCostColumns()` in `messageExtraColumns` (after `ALTER TABLE message ADD COLUMN harness_cost_usd REAL;`, shipped in the chat template as `migrations/0007_harness_cost.sql`) stores the harness spend, or null when the harness reported none. On a store without the column, messages read, insert and update as before and the harness spend is not stored; turn receipts still carry it.
